# Incidents and the rules they left behind

Dated failures from steps 23 to 27, kept so the rule in SKILL.md ("Gotchas") can be traced to what happened. Add new entries at the top; when a fix lands in a script, say so here and keep only the rule in SKILL.md.

| Date / step | What happened | Rule or fix |
|---|---|---|
| 2026-10-12, step 25 | A chain script ended with `rm -f results/bobbm.kubeconfig` while `run-point.sh` calls of another script on the same `RESULTS` still used that file; they waited 11 h on "kubectl cannot reach the cluster" until a new point recreated it (`pin_kube`), then fetched normally | Never delete the pinned kubeconfig while runs may share `RESULTS`; `run-sweep.sh` leaves it (git-ignored as `*.kubeconfig`) |
| 2026-10-11, step 25 | vLLM hit "CUDA error: an illegal memory access" three times, always on one spot H100 node, in both arms (so not the gate); no other node crashed in about 25 CPU-offload points. The pod's logs went with it. With CPU offload the crashed container could not restart: the old offload file still filled `/dev/shm` ("Insufficient space in /dev/shm"), and aiperf stopped at its 10% failed-request threshold | Read the crash in Cloud Logging (`gcloud logging read 'resource.labels.pod_name="<pod>"'`), then cordon the node |
| 2026-10-09, step 24 | GKE scaled down a spot H100 node that held one lane pod ("deleting pod for node scale down"); the point failed the 10% error threshold. Moving lane pods around also made the autoscaler add a node in another zone | `run-point.sh` annotates every target pod `cluster-autoscaler.kubernetes.io/safe-to-evict=false` |
| 2026-10-09, step 24 | A script was edited while a lane was running it; bash reads a running script from the file as it goes, so the running copy executed shifted bytes and the lane broke | Never edit a script while a run uses it; finish or stop the runs first |
| step 24, phase 2 | The first lane claim excluded pods that existed before the lane's own delete. With four lanes restarting within seconds, two lanes took each other's replacements and two waited 45 min for a pod that never came | Fixed in `run-point.sh`: lanes never remove their label, so any unclaimed pod has served no point and is fresh |
| step 24 | A plain `\d+` pattern silently missed aiperf's thousands separators (`completed=1,269, cancelled=30`), so every thunder point with 1,000+ requests showed 0 cancelled | Fixed in `analyze.py` (`phase_counts`), covered by `tests/test_analyze.py` |
| step 24, offload c192 | The GKE auth plugin failed for minutes ("print credential failed"); with `set -e` one failed kubectl call ended `run-point.sh` while the job ran on | `run-point.sh` waits up to 30 min for the API (`wait_api`); if a point still ends early its data is on the PVC and can be fetched afterwards |
| step 24 | `analyze.py` on a c=192 point needed about 5 GB and stalled the laptop when memory was short; it blocked `run-lanes.sh` before the next wave | `read_server` skips histogram bucket rows (81% of the parquet); analyses can be rerun later |
| step 24 | Lane envoy reused a connection vLLM had closed after 5 s idle and returned 503 "reset before headers: connection termination"; AgentX aborts on one failed root warmup request. Gate holds make connections idle longer, so only router arms hit it | `manifests/lane-epp-values.yaml` sets the upstream `idle_timeout` to 4 s |
| step 24 | `kubectl apply` of a lane EPP failed with "ENHANCE_YOUR_CALM" and left half the objects missing | Retry the apply (the step 24 scripts' `apply_retry`) |
| step 23 | thunder c32: 1132 of 1298 EPP queue waits were counted because per-flow series that appear mid-window were based at their first value, not 0; the histogram buckets looked non-monotonic | Fixed in `router_metrics.epp_increase`: a series first seen after the window start starts from 0 |
| step 23 | On `lane-20m` c=32, 53% of completions came in the first 5 minutes (lanes waiting out recorded first-request gaps until the 300 s per-tree idle cap); p50 tok/s/user was 43.7 whole run against 7.7 after minute 5 | `ss_*` columns and the sweep figures use requests started after `--skip-minutes` (default 5) |
| step 23 | The aiperf server-metrics CSV and JSON counter totals included the warmup (CSV prompt tokens = profiling delta + warmup ISL) | `analyze.py` reads only the parquet, which covers the profiling window |
| steps 16 to 21 | `helm upgrade --reuse-values` broke the EPP release, and Helm keeps only 10 revisions, so a rollback by number was not possible | Save `helm get manifest` before touching the main release; restore by saved manifest (`16-thunder-minimal-pool/restore-main-release.sh`) |
| operator note | In zsh an unquoted variable holding several file names is not split, so a `grep -c` over it in a watch loop counted nothing | Run watch loops with `bash -c` |
